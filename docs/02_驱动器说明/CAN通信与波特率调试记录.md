# CAN 通信与波特率调试记录（2LD2-CAN7020B 台架）

> 日期：2026-11-19
> 对象：台架上的 2LD2-CAN7020B 双轴驱动器（两轴电机均已接）+ PEAK PCAN-USB Pro FD（`can0`）
> 目的：确认主站侧 CAN 链路可用、确认驱动器实际波特率与站点配置
> **配置基准值与操作步骤以 [驱动器配置基准](驱动器配置基准.md) 为准**；本文件只保留排查过程与证据
> 相关：[双轴驱动器配置说明](双轴驱动器配置说明.md) · [2LD2-CAN7020B 双轴驱动器说明](2LD2-CAN7020B双轴驱动器说明.md) ·
> 手册：[2LD2-CAN 系列用户使用手册 V1.6](2LD2-CAN系列(7030,7020,7015)用户使用手册V1.6_2987500915933462.pdf)

## 1. 结论摘要

| # | 结论 | 证据 |
|---|---|---|
| 1 | **两轴实际波特率不一致**：节点 1 = **250k**，节点 2 = **125k** | 250k 下只有 0x701 应答、`2024h = 3`；125k 下节点 2 回 `0x582`，`2023h = 2` |
| 2 | 因此**任何单一速率下都无法稳定同时通信**，总线上持续有错误帧（PCAN 红灯闪） | 各速率扫描时另一方在场制造错误帧，接口频繁 `ERROR-PASSIVE` / `BUS-OFF` |
| 3 | **1M 从未成功过**：1M 下发帧无 ACK，直接 BUS-OFF | `TX packets=1, errors=11 → BUS-OFF`；原因链 = 两轴都不在 1M |
| 4 | 500k 曾两轴同时正常（0x701 + 0x702 都在） | 说明分裂是后来形成的；拨码共用 `SW3/SW4`，分裂成因待查 |
| 5 | 初始 `6041h = 0x0400`（Not ready）**根因是未发 NMT Start**，不是硬件故障 | NMT Start 后 `6041h` 立即变 `0x0650`（详见配置基准 §3） |

## 2. 环境与工具

- 适配器：PEAK **PCAN-USB Pro FD**（双通道，`can0`/`can1` 都在，实测接在 `can0`）
- 驱动：SocketCAN（`peak_usb`），经典 CAN 模式；`python-can 4.3.1`、`candump/cansend` 可用

## 3. 核心发现：两轴波特率分裂

### 3.1 扫描证据（以 125k~1M 逐个监听）

| 监听速率 | 收到的帧 |
|---|---|
| 1M（默认） | 无 |
| 1M + `sample-point 0.875` | 无 |
| 800k | 无 |
| 500k | 无 |
| 250k | `0x701 [1] 7F`（节点 1 心跳，1 Hz） |
| 125k | `0x582 [8] 43 23 20 00 02 00 00 00`（节点 2 应答，`2023h` = 2） |

### 3.2 各节点自报参数

| 读数 | 节点 1 | 节点 2 |
|---|---|---|
| `2023h` 站号 | 1 | 2 |
| `2024h` 波特率码 | **3（250k）** | 未在 250k 下读到；在 125k 下可通信（按码表应为 **4 = 125k**，待复读确认） |
| `1000h` 设备类型 | 0x00020192 | 0x00020192 |
| `6502h` 支持模式 | 0x3002D（含 PP / PV / PT） | 0x3002D |
| `608Fh:01/02` 编码器 | 131072 / 1（编码器计数，不是指令单位） | 131072 / 1 |
| `6091h` / `6092h` 齿轮比 | **读回 abort `0x06020000`（对象不存在）**；原表记为 1/1 与 10000，2026-11-20 复测作废 | 同左 |
| `6060h` 目标模式 | 1（PP） | 1（PP） |
| `6041h` 状态字 | **0x0400 = Not ready to switch on** | **0x0400 = Not ready to switch on** |
| `603Fh` 故障码 | 0 | 0 |
| `6064h` 实际位置（读数时刻） | 5346 | 373 |

### 3.3 成因疑点（待查）

- 手册 §3.12：`SW3/SW4` 是**两轴共用**的波特率拨码 —— 共用开关理论上不能产生 250k/125k 分裂
- 候选解释：
  1. 拨码改动后**没断电重启**，两轴各自锁存了不同时刻的档位
  2. 驱动器的 `Pr0.24`（`2024h`，按轴独立存储）出厂值不同，拨码只覆盖了其中一轴
- 手册自身矛盾（已知）：§3.12/§8.2.1 写 off/off = 默认 1MHz，但 `Pr0.24` 表写默认值 1 = **800kHz**；
  实测当前 `SW3=SW4=off` 时**没有**出现 1M/800k，而是 250k（节点 1 自报码 3）—— **拨码映射待实测钉死**

## 4. 1M 不通的排查记录

### 4.1 现象

- 1M 下向节点 1~4 发只读 SDO（读 `1000h`）：**全部无应答**
- 发帧统计：`TX 1 帧 → errors 11 → BUS-OFF` ⇒ 总线上**没有任何节点对 1M 帧做 ACK**
- 多次尝试 1M 时 `rx` 错误计数满格（127）⇒ 有其他节点在不匹配的速率上持续发帧

### 4.2 电脑端位定时笔记（SocketCAN）

| 速率 | 驱动自动选择的位定时 | 备注 |
|---|---|---|
| 1M（默认） | `sample-point 0.750`，`tq 12.5ns`，`brp 1` | **非 CANopen 惯例 87.5%**；1M 是唯一被驱动挑成 75% 的档位 |
| 1M + `sample-point 0.875` | `prop 34 + phase1 35 + phase2 10`，sp=87.5% | 可设置成功 |
| 500k/250k/125k | sp≈87.5% | 与常规设备一致 |
| `bitrate 1000000 sample-point 0.85 tq 50` | **`RTNETLINK: Invalid argument`** | iproute2 不允许 bitrate+sample-point+tq 三者同时给；强制 tq 要用原始定时：`tq <ns> prop-seg <n> phase-seg1 <n> phase-seg2 <n> sjw <n>` |

### 4.3 当前判定

**主因不是采样点，而是两轴波特率分裂**：任何速率下总有另一个节点在"捣乱"，无法形成干净通信。
采样点差异（75% vs 87.5%）只作为 1M 的次要变量，等两轴统一到 1M 后再复核。

## 5. 常用命令（本机）

```bash
# 拉起/切换波特率（需 root；BUS-OFF 后重跑即可恢复）
sudo ip link set can0 down && sudo ip link set can0 up type can bitrate 500000 restart-ms 100

# 1M 显式 87.5% 采样点
sudo ip link set can0 down && sudo ip link set can0 up type can bitrate 1000000 sample-point 0.875 restart-ms 100

# 被动监听（含心跳 0x701/0x702）
candump can0

# 查看状态与错误计数
ip -details -statistics link show can0
```

- 强制 brp 的写法（1M 排查备用）：`type can tq 50 prop-seg 15 phase-seg1 1 phase-seg2 3 sjw 3`
- 排障要点：**发一帧看是否 BUS-OFF** = 判断"有没有节点在正确速率上做 ACK"的最快方法
