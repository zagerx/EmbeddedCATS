# 分层与线程模型

本文件是**目录与线程的契约**。改代码前先看这里；改完代码用
`firmware/apps/tools/layering_check.sh` 自检。

固件源码根是 `firmware/controller/`（名字取"控制器源码"，避免与其中的"组合根"层重名）：
七个层目录平铺在它下面，控制层自己的文件（`controller.c` 组合根 /
`control_api.c` 状态机侧 / `controller_internal.h`）
也平铺在根上，不再单独占一层目录。另有 `config/`（机械参数与 PDO 配置表，不是一层）。

---

## 一、八个目录，一句话定义

| 目录 | 一句话定义 | 允许依赖 | 不知道什么 |
|---|---|---|---|
| `bus/` | 一帧 CAN 的收发能力 | 平台头 / socket | 任何协议、COB-ID 语义、线程 |
| `canopen/` | DS 301 客户端服务栈：COB-ID / NMT / 心跳 / SDO 客户端 | 无（只靠注入的 tx 发帧） | 有几个从站、402 对象号、使能、轴、单位 |
| `master/` | 主站实体：一条总线 + 登记的从站（站号表 / 收发分派） | `canopen`、`bus` | 402、对象语义、轴、业务状态 |
| `ds402/` | DS 402 标准知识：状态枚举/位/对象号 + **PDS 序列表与起点快进** | **无** | 总线、时间、循环、超时、线程、单位 |
| `drive/` | 一个 402 从站的运行期：意图槽 + 同步流程（序列推进 / PP）+ 对象访问 | `ds402`、`od_access`、`backends`→`canopen` | CAN 帧、COB-ID、业务状态机、mm |
| `axis/` | 单位换算、限幅、指令流 | `drive` | 402 位定义、对象号、CAN |
| `statemachine/` | 本机业务状态图（PREPARING / RUNNING / ESTOP…） | `hsm`、`axis` | 402、CAN、对象号、SDO |
| `hsm/` | 通用层次状态机内核（零业务依赖） | 无 | 任何业务词、轴、协议 |
| `controller/` 根 | 装配（`controller.c`）、对外 API 的状态机侧（`control_api.c`）、契约（`include/control/control.h`）；**不创建线程** | 全部 | —（它只调各层对外接口） |

**`drive` 的粒度**：一个 `drive` = **一个 CANopen 402 从站**（一对 `0x600/0x580`、一个轴）。
物理设备 `2LD2-CAN7020B` 是双轴驱动器 = **2 个从站 = 2 个 `drive` 实例**。

**`canopen` 与 `master` 的分工**：
- `canopen` 是**协议栈**（对标 CANopenNode 的 `CO_SDOclient` / `CO_HBconsumer`）：
  给定"站号 + 一帧字节 + 当前时刻"，它回答"该发什么、这帧什么意思"。
  **它不知道这台机器上有几个从站**。
- `master` 是**主站实体**：一条总线 + 站号表 + 收发分派 + "掉线 750 ms 算死"。
  它不认识对象号，也不认识"轴"。

**DS 402 不是 `canopen` 的子目录**——那是另一个标准，可以脱离 CANopen 存在（CoE 等）。

## 二、依赖方向（严格单向）

```text
control ──> statemachine ──> axis ──> drive ──> ds402
   │                                    │
   │                                    └──> od_access ──> backends ──> canopen
   └──────> master ──> canopen              (master 注入 tx，canopen 不认 bus)
```

- `ds402/` 零依赖（连 `canopen` 都不能出现）；
- `canopen/` 不认识 `master/`、没有站号表（R9）；
- `drive/src/backends/`、`master/` 与组合根可以 include `<canopen/…>`（R3）；
- 任何一层不得 include 上层。

## 三、线程模型：3 个工作线程 + 1 个 UI 线程

**线程不由 controller 创建**：`controller/` 只提供三个"推进一步"的接口
（`cats_control_io_poll` / `cats_control_poll` / `cats_control_svc_poll`），
线程与节拍由 `apps/` 下的宿主编排（R8 检查：controller 里不得出现 `pthread_create`）。
参考实现：`apps/qt/bindings/can_thread.cpp`、`apps/tools/master_probe/main.c`。

| 线程 | 由谁起 | 调什么 | 独占的东西 | 禁止 |
|---|---|---|---|---|
| **① I/O** | 宿主 | `cats_control_io_poll()` | **`bus`（唯一收发者）** | 不决定"该读什么对象" |
| **② 控制** | 宿主（可与 ① 同线程） | `cats_control_poll()` | 状态机与轴对象 | **零 I/O、零阻塞、零 malloc** |
| **③ 服务** | 宿主（**必须独占**） | `cats_control_svc_poll()` | 无（串行） | 不泵总线 |
| **④ UI** | Qt | 只读快照、投事件 | 无 | 不回写任何层 |

- **唯一的等待点**：`od_sdo` 的 `pthread_cond_timedwait` / `bus` 的 `poll(fd)`；
  任何等待禁止写成 `while (!ok) usleep(...)`。

### 三条硬规则

1. **谁收帧必须唯一**：`bus` 只由 ① 使用。两个线程同时 `recv` 会互相偷帧。
2. **谁能等必须不在 ①②**：阻塞式调用（SDO 事务、`run_to`）只能出现在 ③。
3. **谁能发帧可以多个**：但一律经 TX 队列，由 ① 真正 `write()`。

### 超时归属

| 概念 | 归谁 | 含义 |
|---|---|---|
| `txn_timeout_ms`（如 200 ms） | `sdo_channel` | 从帧发出算；超时 = 该通道/节点不正常 |
| `caller_ms`（业务耐心） | `od_sdo` 适配层 | 愿意等多久；可跨多次事务重试 |
| 定时来源 | ① 每拍带超时调 `recv()`（超时 = 距最近一个 deadline 的余量）| **不轮询** |

## 四、边界检查（`apps/tools/layering_check.sh`）

| 规则 | 判据 |
|---|---|
| R1 | `ds402/` 里不出现 `canopen` / `0x600` / `0x580` |
| R2 | `canopen/` 里不出现 402 对象号（`6040/6041/6060/6061/607A/6064/606C/603F`） |
| R3 | 只有 `master/`、`drive/src/backends/`、`controller/include/`、`controller/*.c`
  可以 `#include <canopen/…>` |
| R4 | 控制线程的代码里不出现阻塞调用（`run_to`/`wait`/`sleep`） |
| R5 | `bus/` 里不出现协议词（`nmt`/`sdo`/`pdo`/`0x600`/`0x580`） |
| R6 | `statemachine/` 里不出现协议对象号与 `drive`/`canopen` 的私有头 |
| R7 | `hsm/` 里不出现业务词（轴、使能、故障码…） |
| R8 | `controller/` 里不创建线程（无 `pthread_create`） |
| R9 | `canopen/` 里不出现主站词汇（`master_*`、`node_count`、`<master/`） |
| R10 | `master/` 里不出现 402/业务词汇（对象号、`ds402`、`cats_`、`stm_`、`<drive/`） |

规则只看代码，纯注释行不计（注释里解释"本层不知道 402"不算依赖）。

判据说明：分层的价值是可校验。**任何"约定"只要不能一条命令检查，就一定会漂。**

## 五、验收口径

改完任何一层，下面四步都要过：

1. `cmake --build build -j4` —— 零 error / 零 warning；
2. `./build/canopen_selftest` —— 全部通过；
3. `apps/tools/layering_check.sh` —— R1–R8 全绿；
4. 端到端跑一次：

```bash
python3 apps/tools/fake_drive/fake_drive.py -i can1 -n 1,2 &
timeout 30 ./build/master_probe can0 6 --move 5 --move-at 1000 --stop-at 1800
```

期望状态流：`PREPARING → CONFIGURING → ENABLING → HOLDING → MOVING → HOLDING`，末了正常停车。

**"编译通过"不等于"跑得对"**：装配漏了调用、线程抢总线这类错误，只有第 4 步能抓出来。
