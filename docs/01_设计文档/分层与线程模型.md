# 分层与线程模型

本文件定义目录、依赖和线程契约。修改后运行 `firmware/apps/tools/layering_check.sh` 自检。

## 一、目录职责

| 目录 | 职责 | 允许依赖 |
|---|---|---|
| `bus/` | 一帧 CAN 的收发 | 平台头 / socket |
| `canopen_node/` | CANopenNode CO_driver 移植层 | `bus` |
| `master/` | 一条总线、节点表、NMT、心跳与协议栈推进 | CANopenNode、`canopen_node`、`bus` |
| `transport/` | `sdo_access` 对象访问契约及 CANopen SDO 后端 | 契约无依赖；SDO 后端依赖 CANopenNode |
| `cia402/` | DS402 标准知识与单从站运行控制 | 设备层依赖 `sdo_access`；PDS 纯知识无依赖 |
| `axis/` | 单位换算、轴命令与反馈 | `cia402` |
| `statemachine/` | 整机业务状态图 | `hsm`、`axis` |
| `hsm/` | 通用层次状态机内核 | 无 |
| `controller/` 根 | 装配、对外 API 与三个推进接口 | 上述各层公共接口 |

`config/` 保存机械参数与 CANopen 对象字典，不是独立业务层。

### CiA 402 内部边界

```text
cia402/pds      纯函数：状态解析、序列表、起点快进
cia402/device   运行期：请求、流程推进（配置/使能/停止同步，PP 分步）、超时、取消、反馈
```

一个 `struct cia402_device` 对应一个从站。双轴驱动器是两个 CANopen 节点，因此有两个设备实例。

`transport/sdo_client` 不属于 CiA 402 核心：DS402 只要求对象字典访问，不应绑定 CANopen 传输。

### CANopen 各部分的边界

- CANopenNode 提供 NMT、心跳消费和 SDO 客户端协议机制，不知道本机节点数量或轴。
- `master` 持有节点表并推进协议栈，不认识 402 对象语义。
- `transport/sdo_client` 将步进式 SDO 客户端包装成服务线程可等待的 `sdo_access`，不实现 402 流程。
- `cia402/device` 决定读写哪些 402 对象以及如何判断流程成功。

## 二、依赖方向

```text
control ──> statemachine ──> axis ──> cia402/device ──> cia402/pds
   │                                    │
   │                                    └──> sdo_access <── canopen_sdo ──> CANopenNode
   ├──────> canopen_sdo
   └──────> master ──> CANopenNode ──> canopen_node ──> bus
```

- `cia402/pds.c` 及其公共类型不依赖传输、线程、时钟或单位。
- `cia402/device*.c` 只依赖 `sdo_access`，不得 include CANopenNode。
- 只有 `master/`、`transport/` 的 SDO 后端、`canopen_node/` 和对象字典可以 include CANopenNode 头。
- 任何下层不得 include 上层。

## 三、线程模型

`controller/` 不创建线程，只提供三个推进入口；线程与节拍由 `apps/` 宿主编排。

| 线程 | 调用 | 独占资源 | 约束 |
|---|---|---|---|
| I/O | `controller_io_poll()` | 总线与 CANopenNode | 非阻塞 |
| 控制 | `controller_poll()` | 状态机 | 零 I/O、零阻塞、零 malloc；可与 I/O 同线程且后调用 |
| 服务 | `controller_svc_poll()` | 同步设备流程 | 独立线程；允许等待对象事务 |
| UI | 查询快照、投递命令 | 无 | 不直接修改控制对象 |

参考实现：`apps/qt/bindings/can_thread.cpp`、`apps/tools/master_probe/main.c`。

### 硬规则

1. 只有 I/O 线程调用总线接收。
2. 阻塞式对象访问和 402 流程只在服务线程执行。
3. 协议栈只在 I/O 线程推进；发送可经协议栈或队列最终交由 I/O 路径执行。
4. 等待使用条件变量或带超时的 `poll`，不使用忙等。

### 超时

- `txn_timeout_ms`：单次 SDO 事务的响应超时，由 SDO 通道管理。
- 402 步骤、运动和停止超时：由 `cia402/device` 管理。
- 宿主导调用节拍不负责解释设备超时。

## 四、分层检查

| 规则 | 判据 |
|---|---|
| R1 | CiA 402 纯 PDS 文件不出现 CANopen、传输或 COB-ID 依赖 |
| R2 | `canopen_node/` 不出现 402 对象号与设备语义 |
| R3 | 只有 `master/`、`transport/` SDO 后端、`canopen_node/`、对象字典可 include CANopenNode 头 |
| R4 | 控制线程不出现阻塞调用 |
| R5 | `bus/` 不出现协议词或 CANopen COB-ID |
| R6 | `statemachine/` 不出现协议对象号或下层私有头 |
| R7 | `hsm/` 不出现业务类型与词汇 |
| R8 | `controller/` 不创建线程 |
| R9 | `canopen_node/` 不出现主站节点表 |
| R10 | `master/` 不出现 402 或业务词汇 |

纯注释行不计为依赖。规则需要随目录契约同步更新，不能只改文档。

## 五、验收

```bash
cmake -S firmware -B firmware/build
cmake --build firmware/build -j4
./firmware/build/cia402_selftest
firmware/apps/tools/layering_check.sh
python3 firmware/apps/tools/fake_drive/selftest.py
```

端到端验证需要先配置 `can0` 主站与 `can1` 模拟从站：

```bash
python3 firmware/apps/tools/fake_drive/fake_drive.py -i can1 -n 1,2 &
timeout 30 firmware/build/master_probe can0 6 --move 5 --move-at 1000 --stop-at 1800
```

期望状态流：`PREPARING → CONFIGURING → ENABLING → HOLDING → MOVING → HOLDING`，最后正常停车。
