# CiA 402 模块边界

## 定位

`cia402` 是**单轴操作与对象访问协调器**。一个实例对应一个从站，负责完成一项操作并报告结果，不是实时设备状态镜像，也不是后台监测器。

## 负责

- 执行 `CONFIG / ENABLE / DISABLE / MOVE / HALT / QUICK_STOP`。
- 流程需要时读取相关对象，判定步骤和结果。
- 管理单槽请求、单操作流程、单笔 SDO 的关系。
- 普通请求的前置检查与忙拒绝；停车请求抢占普通流程。
- 报告主站确认结果、操作回执和诊断信息。
- 提供反馈对象的 402 索引定义，不提供反馈缓存或读取调度。

## 不负责

- 不处理 CAN 帧、SocketCAN、COB-ID。
- 不管理多个轴、整机状态或整机故障策略。
- 不换算业务单位，不创建线程，不阻塞等待。
- 不自主轮询反馈，不决定反馈读取时机和周期。
- 不根据反馈自行决定整机故障或恢复动作。

## 对外数据

| 数据 | 含义 |
|---|---|
| 操作状态与回执 | 当前操作、完成结果、失败原因、abort 码 |
| 主站确认结果 | 已确认的 PP 模式、使能等流程前置条件 |
| 对象索引 | 反馈读取所需的 402 标准对象号 |

流程结论不得混为“设备实时状态”。

## 反馈读取

反馈读取就是一次普通 SDO 读取，由控制器使用对象索引直接发起并保存结果。

- 控制器决定读什么、何时读、是否重试以及如何使用结果。
- 反馈不走 SDO：`canopen/pdo` 解好 TPDO，控制层只搬运快照。
- 因此 SDO 通道只有一个使用者：402 控制流程自身。
- 流程内部读取属于当前操作，由该流程自行发起。
- 402 不保存外部反馈缓存；读取结果的有效性由控制器管理。

## 线程与存储

- 所有实例字段仅由同一个 CANopen 工作线程访问。
- 普通调用方只包含 `device.h`，使用不透明实例指针。
- 对象所有者为静态存储包含 `device_instance.h`，但不得读写内部字段。
